# sdp-tunnel

[English](README.md) · **简体中文**

一个运行在用户态的企业 SDP 网关客户端。它完成认证、建立网关的三层隧道、在网关下发的地址上跑自己的 TCP/IP 协议栈，并把这个网络以本地 SOCKS5 与 HTTP 代理的形式提供出去。

不需要 TUN 驱动，不需要管理员权限，不改动主机路由表。一个静态二进制。

```
    应用程序
       │
       ├──► SOCKS5  127.0.0.1:1080 ─┐
       └──► HTTP    127.0.0.1:8080 ─┤
                                    │
                                    ▼
                     用户态 TCP/IP（gVisor netstack）
                                    │   跑在网关下发的虚拟 IPv4 上
                                    ▼
                      TLS 之上的分帧三层隧道
                                    │
                                    ▼
                                   网关
                                    ▲
                                    │   控制面 API（HTTPS）：
                                    └── 取密钥、验证码、登录、取策略、会话换发
```

## 为什么放在用户态

常规 VPN 客户端要装虚拟网卡、改路由表，于是需要驱动和提权。这个客户端在进程内终结 TCP 与 UDP，把结果通过一个环回代理端口交给任何来问的程序。实际好处是：

- 以普通用户身份运行；
- 不碰主机自身的网络配置，因此可以和机器上已有的任何 VPN、代理或 TUN 工具共存；
- 分流决策权归你指向代理的那个程序，而不是归本客户端。

## 已实现的部分

- 认证：会话密钥、验证码、AES-128-CBC 口令线格式、带原子替换的会话缓存。
- 控制面拒绝缓存会话时，先走无验证码的会话换发；换发也失败才退回完整登录。
- TLS 之上的分帧三层隧道，虚拟地址与子网掩码均取自网关自己的握手属性。
- 在下发地址上的用户态 IPv4 TCP 与 UDP；DNS 走隧道，向认证策略指定的解析器查询。
- SOCKS5（`CONNECT` 与 `UDP ASSOCIATE`）和 HTTP 代理（`CONNECT` 与普通转发）两种入站。
- 向控制面注册与释放地址租约。
- 重连会重建一整代——新协议栈、新套接字——因此没有任何状态跨越一次断线，同时丢弃池化在已死隧道上的连接。

未实现：IPv6（网关不下发）、单包授权敲门（实测环境中该功能本身是关闭的）、以及部分客户端使用的第二条传输通道。每一处缺省都是有测量依据的决定，不是遗漏。

## 构建

只需要 Go 1.27 或更高版本，没有其它依赖。

```sh
go build -trimpath -ldflags='-s -w' -o bin/sdp-tunnel ./cmd/sdp-tunnel
go test ./...
```

`go test -race ./...` 另外需要一套 C 工具链。

## 配置

把 `config.example.json` 复制为 `config.json` 并填写。所有随部署环境变化的值都在这里，代码里一个也没有。

| 字段 | 含义 |
|---|---|
| `gateway.host`、`gateway.port` | 网关地址与端口 |
| `gateway.bind_ip` | 可选的本地源地址；单网卡主机请留空，交给操作系统选路 |
| `gateway.ca_file` | 可选的额外 PEM 根证书，追加到系统信任库而不是替换它 |
| `gateway.mtu` | 隧道 MTU，默认 1400 |
| `protocol.api_base` | 控制面 API 的路径前缀 |
| `protocol.user_agent` | 控制面期望的客户端标识串 |
| `protocol.session_cookie` | 把取密钥、验证码、登录串起来的那个 Cookie 名 |
| `protocol.renew_salt` | 控制面在会话换发摘要中要求的盐值 |
| `captcha.model` | 验证码模型文件路径，见下文 |
| `auth.username`、`auth.password` | 凭据；若缓存会话已够用，两者都可以不填 |
| `inbounds` | 一个或多个 `socks5` / `http` 监听器 |

文件内的相对路径按配置文件所在目录解析。`config.json` 已被 git 忽略，所有 `.bin` 也一样，所以你的凭据和模型都不可能被误提交。

### 验证码模型

登录要读控制面给出的验证码。本仓库只提供识别**引擎**，不提供模型：训练好的模型只对某一个网关的验证码有效，因此它和凭据一样属于部署制品。

把 `captcha.model` 指向一个模型文件即可。该格式是自描述的，引擎里不保留任何属于某个具体验证码的常量：

```
偏移    长度       字段
0       4          magic "MCNN"
4       4          版本号 = 2
8       4          图像宽
12      4          图像高
16      4          字符槽位数
20      4          inset：字形被缩放到 32x32 单元格内这么多像素以内
24      4          背景阈值：各通道都 >= 此值的像素算背景
28      4          噪声跨度：某个颜色横跨的列数超过此值即判为干扰线
32      4          字母表长度 N
36      N          字母表字节（ASCII）
36+N    槽位数 * 8  兜底区间，每个为一对 uint32（start, end）
...     12         拓扑：第一层卷积核数、第二层卷积核数、全连接单元数
...                权重：conv1 w/b、conv2 w/b、dense1 w/b、dense2 w/b，小端 float32
```

字母表是一张下标到字符的表，允许重复项——这正是「模型的类别区分大小写、但输出只用一种大小写」的实现方式：引擎自己不做任何大小写折叠。

引擎只跑一种固定拓扑——在 32x32 字形单元格上做两轮「3x3 卷积 + ReLU + 2x2 池化」，再接两层全连接——模型若声明别的拓扑，引擎直接拒绝，而不是算错。其上限为 320x96 像素、8 个槽位、95 个类别。

没有模型时客户端仍可恢复缓存的会话，只是无法从零登录。

## 运行

```sh
./sdp-tunnel -c config.json          # 启动配置好的入站
./sdp-tunnel -c config.json -check   # 仅校验缓存会话与握手
./sdp-tunnel -v                      # 版本
```

然后把想走隧道的流量送到代理端口。若使用 sing-box、Xray 之类的分流客户端，把本地 SOCKS5 端口声明为一个出站，再匹配那些应当走网关的目标。有两条规则很关键：

1. 网关自身的地址必须**直连**。把它也丢进本代理，等于要求隧道承载自己的传输层。
2. 这条直连规则要放在任何可能匹配到网关域名的宽泛规则**之前**。

## 已知行为

**网关大约每九分钟掐断一次隧道。** 跨多次独立运行测量，断线时刻都落在分钟内的同一个秒偏移上，这说明是网关上的一个定时清理任务，而不是客户端做了或没做什么。它也不是空闲超时：该间隔与流量无关，任何保活手段都挡不住。

客户端约一秒内用缓存会话重连，并丢弃池化在已死隧道上的连接，使调用方看到的是一次重连而不是一条坏掉的流。那一刻正在传输中的流确实会断——它们的数据通路已经不存在了——客户端侧没有任何改动能避免这一点。

## 适用范围

这是一个独立客户端，依据观测到的协议行为写成，与任何厂商无隶属关系、也未获其背书。请用你自己的凭据、在你有权使用的网络上、按你账号适用的条款使用它。它自动化的是你本来就有权完成的登录；它不绕过认证，也不授予你的凭据本身得不到的任何访问权限。
